# Comparison with the reference repository and measured improvements

Reference: `opencv/opencv_zoo/models/face_detection_yunet` — a face **detection** demo (detector weights + ~150 lines of demo code). It has no recognition, enrolment, liveness, persistence, API, security or UI. The table states what each side actually provides and how FaceGate's claim was verified on this machine (Intel i5-1135G7, 4 cores, no GPU).

| Area | Reference repository | FaceGate | Evidence |
|---|---|---|---|
| Facial recognition | None (detection only). | One-to-many identification: SFace 128-d embeddings, 5 templates per employee, cosine match with accept threshold **and** second-best margin → `identified` / `unknown` / `ambiguous`. | `tests/test_vision.py::test_identification_rules` (self-match > 0.95, unknown rejected, near-duplicate → ambiguous, empty index → no decision); `test_e2e_stream.py` (known face identified at score > 0.8, unknown face rejected end-to-end). |
| Liveness detection | None — a printed photo is detected like a live face. | Passive PAD (MiniFASNet V1SE + V2, two crop scales, averaged over ≥ 4 frames) **and** a server-chosen head-turn challenge verified from landmark geometry; both gates precede matching. | PAD scored 0.96–0.999 "live" on 5/6 clean synthetic stills and 0.31 on one (`docs/05`); challenge state machine unit-tested (`test_challenge_state_machine`). Print/screen/replay trials with a physical camera are listed as **pending user execution** in `docs/05` — not claimed. |
| Employee enrolment | None. | Admin-only, consent-versioned, 5-pose guided capture with lighting/blur/size/pose coaching, liveness during capture, cross-pose consistency check, duplicate-identity guard, AES-GCM templates, supersede-on-re-enrol, audit entry. | `test_e2e_stream.py` (duplicate identity for a second employee raises `duplicate_identity`); browser flow in `pages/admin/Enrolment.tsx`. |
| Attendance tracking | None. | Server-side state machine: check-in/out ordering, duplicate-scan window, overnight day boundary, late/early computation, missing-check-out detection, immutable events + audited corrections, daily summaries, CSV/XLSX export, live board. | `tests/test_attendance_engine.py` (4 tests covering ordering, duplicates, lateness, overnight boundary with BST, corrections). |
| Database | None. | 13-table PostgreSQL schema with Alembic migration, derived `attendance_days`, append-only `audit_log`, encrypted `face_templates`. | `alembic/versions/*_initial_schema.py`; migration applied and seeded on Postgres 16. |
| Security | None (trusts any frame). | Argon2id + lockout, TOTP MFA, rotating refresh sessions, RBAC in dependencies, single-use verification tokens bound to session, nonce-checked WebSocket, rate limits, CSP/HSTS, audit trail, no hidden bypass. | `tests/test_api.py` (bad password 401, RBAC 403, token replay 409, PIN fallback gated by admin). |
| User experience | OpenCV `imshow` window. | Landing, kiosk, login (MFA step), dashboard, directory, profile, enrolment, attendance (5 tabs), reports, settings/security/users/audit, employee portal; responsive to 375 px; dark/light. | Chrome DevTools: zero console errors on every page; Lighthouse accessibility 94, best-practices 100 (`docs/05`). |
| Animations | None. | Shared motion tokens; route/page, list stagger, dialog/toast springs, shared-element nav pill, canvas scan frame + sweep + liveness bar, success/failure rings; reduced-motion respected. | `frontend/src/lib/motion.ts`, `components/camera/CameraStage.tsx`. |
| Performance | Single blocking loop. | Bounded inference pool, off-loop JPEG decode, back-pressured WebSocket streaming, load shedding (`busy`), in-RAM template index. | `benchmarks/latency.py`: detect 17 ms, PAD 6 ms, embed 14 ms → **37.5 ms p50 / 54 ms p95 per frame**; match over 1 500 templates 0.44 ms. Load results in `docs/05`. |
| Deployment | `python demo.py`. | Docker Compose (Postgres, API, Nginx TLS, backup), migrations, env templates, README. | `deploy/`. |

## Honest limits of the comparison

- The reference is a component, not a competing product; "improvement" here means building the missing system around a detector of the same family, not beating the detector itself (YuNet is kept because it is the best-licensed lightweight detector with landmarks).
- Recognition thresholds were calibrated on synthetic faces and the author's own live use; a site should run a short FAR/FRR sweep with real staff before relying on the defaults.
- Liveness resistance to printed photos, phone replays and monitor replays has been exercised with the local webcam by the developer but is not certified; see `docs/04` for the threat model.
